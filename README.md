# in-flight-verification

A proof of mechanism for checking each sentence while a model generates, and removing a failed
sentence from the KV cache before anything else is generated on top of it.

It supports the case study
[*Generation-Tier Integrity in Legal RAG via In-Flight Verification*](https://memonsystems.com/case-studies/eliminating-uncontrolled-hallucination-waste/),
which carries the architecture and the cost model. This repository shows the mechanism on one
example. It is not a benchmark and reports no rates.

## The problem

A system that checks an answer only after generation can only reject the whole answer and generate
it again. By then, every token after an ungrounded sentence was generated with that sentence in
context.

Hosted APIs that don't expose the KV cache leave no other option. With the cache in hand, a failed
sentence can be cut out and generation resumed from the last sentence that passed.

## What the two scripts do

Both scripts use the same source passage, the same question and the same ungrounded sentence. The
ungrounded sentence is injected, not generated by the model, so the run is the same every time.

| Script | What it does |
|---|---|
| [`01_attention_contamination_trap.py`](./01_attention_contamination_trap.py) | Check after generation. Generates one grounded sentence, appends the injected sentence to the cache, then feeds a fixed follow-on sentence one token at a time and reports how much attention each token puts on the injected span (mean of the last 4 layers; a token counts as a hit above 5 %). The NLI check runs once at the end, on the whole response. |
| [`02_in_flight_kv_rollback.py`](./02_in_flight_kv_rollback.py) | Check during generation. Each sentence is checked by an NLI cross-encoder against the source passage as soon as it ends. The injected sentence is flagged, the cache is truncated back to the end of the last passing sentence, and generation resumes with a corrective sentence taken from the source. Writes a JSON audit record with a SHA-256 digest over it. |

### What it shows

- After truncation, the cache holds no positions from the rejected sentence, so no later token can
  attend to it. This holds by construction; it is not a measured rate.
- In script 01, the follow-on tokens put measurable attention on the injected span. The script
  prints the per-token figures.
- On this example, the NLI check and the truncation each take milliseconds. Each run prints its
  own latencies for your hardware.

### What it doesn't show

- How often a model produces an ungrounded sentence on its own. The failure is injected.
- That the model would go on to build on the error. The follow-on sentence in script 01 is fixed
  text, used to measure attention, not generated.
- Detection accuracy. One passage and one injected sentence say nothing about the NLI model's
  precision or recall on real legal text.
- What to do after a rejection in general. The corrective sentence here is copied from the source.
- Tamper evidence. The digest proves the record wasn't changed only if the digest is stored
  somewhere the record's writer can't edit.

## Running it

Python 3.10+; Apple Silicon (MPS) or an NVIDIA GPU (CUDA).

```bash
pip install -r requirements.txt

# Checks dependencies, the NLI model and the cache slicing without downloading the generator
python3 01_attention_contamination_trap.py --dry-run
python3 02_in_flight_kv_rollback.py --dry-run

# Full runs
python3 01_attention_contamination_trap.py
python3 02_in_flight_kv_rollback.py
```

Models:

- Generator: `unsloth/Meta-Llama-3.1-8B-Instruct-bnb-4bit` by default; set `GEN_MODEL_ID` to change it.
- Checker: `cross-encoder/nli-deberta-v3-small`, or `-base` if only that is cached; set
  `NLI_MODEL_ID` to change it.

## In a serving stack

Here the cache is sliced in PyTorch along the sequence dimension. In vLLM or SGLang the same
step would be dropping the rejected branch from the prefix cache (RadixAttention) and returning its
pages to the pool (PagedAttention). That integration is not built here.
